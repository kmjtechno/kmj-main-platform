# KMJ native mail — restricted Inbox pilot

Follow-up to #1123 and #1018. Source only, not live. The two independent flags KMJ_MAIL_INBOUND_PILOT_ENABLED and KMJ_MAIL_INBOUND_PILOT_PUBLISH_TEXT both default OFF. No changes to existing MX, routing, Postfix, or account credentials.

A signed, bounded, single-recipient raw MIME message is durably encrypted in quarantine. Under the additional owner-approved publication flag, a strictly limited single-part UTF-8/plain ASCII text message with consistent envelope/header sender, supported transfer encoding, safe text lengths and no attachment disposition can be copied atomically to the configured owner's Inbox. External messages are stored in a separate additive owner-scoped table, with no fabricated KMJ user ID or mutation of existing mail sender constraints. The actual address is shown as unverified. Selection uses a distinct incoming query parameter and marks only the owner's external record read. Compose to sender starts a new draft, not RFC-threaded reply; existing outbound authorization and quotas still apply. The projection stores plain text, not application-encrypted text; raw originals remain encrypted.

Multipart/HTML, uncertain sender identity, malformed headers, unsupported charset, and attachments are retained in encrypted quarantine and never rendered. This is intentionally not a general MIME parser, not SPF/DKIM/DMARC validation, not a malware scanner, not automatic reply, and not full external email support. Some common email clients will send multipart and remain quarantined. No unsupported claims or silent discards.

Before enabling: independent security review; review additive table and all old/new code rollback behavior; verify encryption key custody and backup/restore; verify owner mailbox authorization and bounded ingress; stage exact source and test single-part external email via the isolated pilot alias; verify real External Inbox record and read/unread/compose behavior. Existing info@ forwarding remains untouched. A further audited standards-aware MIME parser, attachment scanning, safe quarantine review/release, sender authentication, RFC reply threading, retention and full external acceptance remain required.
